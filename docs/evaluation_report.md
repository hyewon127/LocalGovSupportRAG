## 2. 평가 설계

### 2.1 질의셋 (WBS 7.1)
- 분석모델 정의서 2.5 방침대로 지역은 서울 고정, 업종·분야 조합 위주로 **관련 질의 27개**를 작성했습니다.
  정답 사업은 질의당 1~9개(평균 4.1개)입니다.
- **무관 질의 6개**는 가드레일 평가용입니다. WBS 5.6에서 임계값 0.77을 정할 때 쓴 질의(날씨/김치찌개/파이썬/손흥민 등)와 겹치지 않게
  새로 썼고, 도메인 단어와 겹치는 함정 질의 2개를 넣었습니다("서울 전시회 추천", "개인 주택담보대출 금리").

### 2.2 정답 라벨링
- **후보 수집(pooling):** 운영 경로(슬롯+하이브리드) top20, BM25 top40, kNN top40, 사업명 키워드 부분검색, 본문 키워드 구문검색
  5가지 결과를 합쳐서 후보를 모았습니다. 시스템 결과만으로 라벨링하면 시스템이 놓친 정답이 후보에서 빠져서 점수가 부풀려지기 때문에,
  사람이 준 키워드 검색으로 보완했습니다.
- **판정 기준:** 공고가 질의가 요구하는 지원을 직접 제공하면 정답으로 봤습니다. 질의 조건과 **충돌**하는 사업은 제외했습니다
  (서울 외 지역 한정, "50대" 질의인데 60세 이상 대상, "예비창업자" 질의인데 사업자등록 필수 등).
  통합 공고는 본문에 해당 세부사업이 실제로 들어 있을 때만 정답으로 인정했습니다. 질의별 제외 근거는 `notes`에 남겼습니다.

### 2.3 어휘 치환 질의 (편향 보완)
관련 질의 27개마다 같은 의도를 **정답 사업명에 쓰인 단어를 피해** 다시 쓴 문장을 뒀습니다. 의도가 같으므로 정답 라벨은 그대로 씁니다.

| 원 질의 | 어휘 치환 질의 |
|---|---|
| 라이브커머스 방송을 해보고 싶은데 제작비 지원해주는 곳 있나요 | 실시간 방송으로 상품을 소개하면서 파는 걸 해보고 싶은데 촬영비를 지원받을 수 있나요? |
| 팁스(TIPS) 프로그램으로 투자 연계 지원을 받고 싶은 스타트업입니다 | 엔젤투자사한테 투자를 받으면 정부가 연구개발비를 매칭으로 더 얹어주는 프로그램이 있다던데요 |
| 회사를 다른 사람에게 넘기려고 하는데 M&A나 기업승계 지원이 있나요 | 은퇴를 앞두고 회사를 자녀나 제3자에게 물려주고 싶은데 도움받을 수 있나요? |

### 2.4 지표 정의
- **순위 기준:** LLM에 넘어가는 top-5 **청크** 순서에서 정답 사업이 처음 나온 위치로 정했습니다.
  같은 사업의 청크가 앞자리를 차지해 다른 사업을 밀어내는 효과도 점수에 반영하기 위해서입니다.
- Hit@k = 앞 k개 안에 정답이 있는 질의 비율 / MRR@5 = 1/(첫 정답 순위)의 평균 / Recall@5(보조) = 정답 사업 중 top-5에 들어온 비율
- 출처 인용률 = 모델이 답한 경우(스스로 "찾지 못했습니다"라고 한 경우 제외) 중, 유효한 `[번호]` 인용이 있는 답변 비율.
  가드레일 **적용 전** 원본 답변으로 잽니다(적용 후에는 인용 없는 답을 이미 버렸으므로 항상 100%가 되기 때문).
- Hallucination(대리 지표) = 인용한 근거에 없는 **수치**(금액/비율/인원 등)를 포함한 답변 비율. 한계는 5장 참고.
- 계산 로직은 `src/evaluation/metrics.py`, 손으로 계산한 기대값과 비교하는 단위 테스트는 `tests/test_evaluation_metrics.py`(25개)입니다.

## 3. 검색 성능 (WBS 7.2)

### 3.1 검색 방식 비교 - 원 질의 (n=27)

| 설정 | Hit@1 | Hit@3 | Hit@5 | MRR@5 | Recall@5 |
|---|---|---|---|---|---|
| **하이브리드 0.4:0.6 (운영 설정)** | **88.9%** | 96.3% | **100.0%** | **0.927** | 67.9% |
| BM25 단독 | 48.1% | 74.1% | 85.2% | 0.621 | 41.0% |
| kNN 단독 | 77.8% | 96.3% | 100.0% | 0.878 | 67.6% |
| 하이브리드, 슬롯 필터 끔 | 85.2% | 96.3% | 96.3% | 0.901 | 67.6% |
| 하이브리드, 사업당 상한 끔 | 88.9% | 96.3% | 100.0% | 0.927 | 67.4% |

### 3.2 검색 방식 비교 - 어휘 치환 질의 (n=27)

| 설정 | Hit@1 | Hit@3 | Hit@5 | MRR@5 | Recall@5 |
|---|---|---|---|---|---|
| **하이브리드 0.4:0.6 (운영 설정)** | 55.6% | **85.2%** | **88.9%** | **0.713** | 45.1% |
| BM25 단독 | 29.6% | 37.0% | 37.0% | 0.327 | 12.2% |
| kNN 단독 | **59.3%** | 81.5% | 85.2% | 0.707 | **46.3%** |

### 3.3 하이브리드 가중치 탐색 - 원 질의 (정의서 탐색 범위 0.2~0.8)

| BM25:kNN | Hit@1 | Hit@3 | Hit@5 | MRR@5 | Recall@5 |
|---|---|---|---|---|---|
| 0.2:0.8 | 85.2% | 96.3% | 100.0% | 0.915 | 67.6% |
| 0.3:0.7 | 85.2% | 96.3% | 100.0% | 0.909 | 68.2% |
| **0.4:0.6 (권장값)** | **88.9%** | 96.3% | 100.0% | **0.927** | 67.9% |
| 0.5:0.5 | 85.2% | 92.6% | 96.3% | 0.892 | 60.1% |
| 0.6:0.4 | 70.4% | 92.6% | 96.3% | 0.812 | 58.7% |
| 0.7:0.3 | 66.7% | 85.2% | 96.3% | 0.785 | 53.1% |
| 0.8:0.2 | 51.9% | 81.5% | 88.9% | 0.677 | 48.0% |

### 3.4 해석
1. **BM25만으로는 부족하고, 성능은 kNN이 끌고 갑니다.** 원 질의에서도 BM25 단독은 MRR 0.621로 목표에 겨우 걸치고,
   어휘 치환 질의에서는 Hit@5가 **85.2% → 37.0%**로 무너집니다. BM25는 질문 단어가 공고에 그대로 있어야 찾는데, 사용자는 공고 제목의 단어를 모릅니다.
   여기에 nori(한국어 형태소 분석기)가 없어서 "벤처나라에"와 "벤처나라"를 다른 단어로 보는 것도 영향을 줍니다(index_mapping.py [알려진 한계]).
2. **하이브리드가 kNN보다 나은 폭은 크지 않습니다.** 원 질의에서는 1등 정확도(Hit@1 88.9% vs 77.8%)와 MRR(0.927 vs 0.878)이 올랐지만,
   어휘 치환 질의에서는 Hit@5 +3.7%p(질의 1개), MRR +0.006으로 차이가 거의 없습니다. 하이브리드의 이점은 "질문에 공고의 고유명사가 있을 때 더 위로 올려주는 것"에 가깝습니다.
3. **가중치 0.4:0.6은 사전에 정한 값인데 탐색 범위에서도 가장 좋았습니다.** 이 값은 이 평가셋을 보고 고른 게 아니라 분석모델 정의서에서
   미리 정한 권장값이라, 같은 데이터로 고르고 평가하는 과적합 문제가 없습니다. BM25 비중을 0.5 이상으로 올리면 모든 지표가 떨어집니다.
4. **설계 결정 검증:**
   - 슬롯 필터(query_slots.py): 끄면 Hit@5 100% → 96.3%, MRR 0.927 → 0.901. 효과는 작지만 긍정적입니다(Q22 "예비창업자" 질의는 "창업" 분야 필터가 있어야 top-5에 정답이 들어옴).
   - 사업당 2청크 상한(hybrid_search.py): **이 질의셋에서는 효과가 없습니다**(Hit/MRR 동일, top-5 내 사업 수 4.1 vs 3.9).
     상한은 "창업 지원사업"처럼 넓은 질의에서 통합 공고 하나가 top-5를 독차지하는 문제(WBS 5.2에서 확인) 때문에 넣은 것인데,
     이 평가셋은 질의가 구체적이라 그런 상황이 거의 없습니다. 넓은 질의를 추가해야 이 결정을 검증할 수 있습니다(6장).
5. **어휘 치환 질의에서 top-5 안에 정답을 못 찾은 3건:**
   - Q18 "산업용 자동화 **기계팔** 신기술 개발비" → 로봇산업기술개발사업을 못 찾고 기계장비 R&D가 나옴
   - Q20 "관공서가 온라인으로 구매하는 **쇼핑몰**에 올리고 싶어요" → "벤처나라"라는 이름을 모르면 연결되지 않음
   - Q26 "회사를 자녀나 제3자에게 **물려주고** 싶어요" → "기업승계"로 연결되지 않음

   세 건 모두 "행정 용어를 모르는 사용자의 표현"과 "공고의 전문 용어" 사이를 임베딩이 잇지 못한 경우입니다.
   개선 방향은 질의 확장(동의어 사전: 물려주기→기업승계, 관공서 쇼핑몰→벤처나라/공공조달)이나 LLM으로 질의를 다시 쓰는 방법입니다.

## 4. 근거 없음 가드레일 (WBS 7.3-A)

가드레일은 top-5 청크의 최고 kNN 점수가 임계값보다 낮으면 LLM을 부르지 않고 "찾지 못했습니다"라고 답합니다(guardrail.py).

**질의 유형별 최고 kNN 점수 분포**
- 관련(원 질의): 최소 0.794 / 중앙값 0.855 / 최대 0.906
- 관련(어휘 치환): 최소 **0.754** / 중앙값 0.803 / 최대 0.904
- 무관: 최소 0.637 / 중앙값 0.724 / 최대 **0.826**

| 임계값 | 관련 질의 통과 (원) | 관련 질의 통과 (어휘 치환) | 무관 질의 차단 |
|---|---|---|---|
| 0.72 | 100.0% | 100.0% | 50.0% |
| 0.74 | 100.0% | 100.0% | 66.7% |
| **0.75** | 100.0% | **100.0%** | 66.7% |
| 0.76 | 100.0% | 85.2% | 83.3% |
| **0.77 (현재)** | 100.0% | **81.5%** | 83.3% |
| 0.78 | 100.0% | 77.8% | 83.3% |
| 0.80 | 96.3% | 55.6% | 83.3% |
| 0.83 | 85.2% | 25.9% | 100.0% |

**현재 임계값 0.77에서 잘못 판정된 6건**
- 관련인데 차단(모두 어휘 치환 질의): Q04 "스킨케어… 도쿄 소비자"(0.758), Q14 "강남 제조업… 싼 이자로 빌리고 싶어요"(0.754),
  Q19 "휠체어… 가게를 차리고 싶어요"(0.770), Q24 "랜섬웨어… 보안 장비 도입 비용"(0.758), Q27 "혼자 가게… 실직 대비 보험료"(0.757)
- 무관인데 통과: O05 "개인 주택담보대출 금리 비교해줘"(0.826)

**해석**
1. 임계값 0.77은 WBS 5.6에서 원 질의 스타일의 질문 10개로 정한 값이라, **실제 사용자 표현(어휘 치환)에서는 정상 질문의 18.5%를 막습니다.**
   관련 질의의 점수가 표현에 따라 0.05 정도 낮아지는데(중앙값 0.855 → 0.803), 그 차이를 반영하지 못했습니다.
2. **"개인 주택담보대출"은 임계값으로 막을 수 없습니다.** 기업 융자 공고와 의미가 가까워서 점수(0.826)가 관련 질의의 중앙값보다 높습니다.
   이걸 막으려고 임계값을 0.83 이상으로 올리면 어휘 치환 질의의 74%가 막힙니다. 점수 하나로 거르는 방식의 구조적 한계라서,
   질의 의도 분류(기업 지원 질문인가)나 LLM의 "근거 없음" 응답(프롬프트 규칙 3)이 2차 방어선이 되어야 합니다.
3. **권장: 0.75로 낮추는 것을 검토.** 0.75면 관련 질의가 원/어휘 치환 모두 100% 통과하고, 무관 질의 차단은 83.3% → 66.7%로 1건 줄어듭니다.
   근거는 **두 오류의 비용이 다르다**는 점입니다. 정상 질문을 막으면 사용자는 답을 잃고 되돌릴 방법이 없습니다. 반면 무관 질문이 통과하면
   LLM이 한 번 더 걸러낼 기회(프롬프트 규칙 3 + 인용 검증)가 남아 있습니다.
   **단, 이 2차 방어가 실제로 작동하는지는 LLM 키가 있어야 확인할 수 있어서, 코드 값은 바꾸지 않았습니다.**
   또 무관 질의가 6개뿐이라 차단율 한 칸(16.7%p)이 질의 1개입니다. 결정 전에 무관 질의를 더 모아야 합니다.

## 5. 답변 품질 - 출처 인용률 / Hallucination (WBS 7.3-B)

**미측정.** `.env`에 `UPSTAGE_API_KEY`가 없어서 LLM 답변을 생성할 수 없었습니다. 결과 파일에도 `"measured": false`로 기록했고, 수치를 추정해서 채우지 않았습니다.

- **측정 준비는 끝났습니다.** 키를 넣고 `.venv\Scripts\python.exe src\evaluation\answer_eval.py`를 실행하면 두 지표와 LLM 포함 응답 시간이 측정됩니다.
- 코드 경로는 `tests/test_answer_eval.py`로 검증했습니다(9/9). 프롬프트를 읽어 답하는 가짜 LLM으로 실제 파이프라인(슬롯 추출 → 검색 → 가드레일 → 프롬프트 → 인용/수치 검사)을
  끝까지 통과시켰고, 일부러 섞은 가짜 금액을 검출하는 것까지 확인했습니다.
- **Hallucination 대리 지표의 한계:** 수치(금액/비율/인원)만 검사합니다.
  - 수치가 없는 지어낸 문장(예: 존재하지 않는 자격 요건)은 못 잡아서, 실제 비율보다 **낮게** 나올 수 있습니다.
  - 근거와 표기 형식이 다른 경우(예: "3천만원" vs "30,000,000원")는 잘못 잡아서 **높게** 나올 수 있습니다.

  정확한 판정이 필요하면 사람이 답변 표본을 근거와 직접 대조해야 합니다(무과금 방침상 LLM 심판은 쓰지 않음).
- 키를 넣으면 슬롯 추출에도 LLM 폴백이 켜집니다(정규식이 아무것도 못 찾은 질의). 그래서 3장의 검색 수치(정규식 슬롯만 사용)와 조건이 달라집니다.
  키를 넣은 뒤에는 `retrieval_eval.py`도 다시 돌려야 비교가 공정합니다.

## 6. 한계

1. **표본이 작습니다.** 관련 질의 27개라서 질의 1개가 Hit@5를 3.7%p 움직입니다. 설정 간 1~2개 차이는 우연일 수 있습니다.
2. **질의와 라벨을 같은 사람(Claude 초안)이 만들었습니다.** 원 질의는 사업명을 본 뒤 작성해서 제목 어휘 편향이 있습니다.
   어휘 치환 질의로 보완했지만, 치환 문장도 같은 사람이 썼습니다. 공고를 보지 않은 사람이 쓴 질의가 가장 공정한 평가셋입니다.
3. **넓은 질의가 없습니다.** "창업 지원사업 알려줘"처럼 정답이 수십 개인 질의가 없어서, 사업당 청크 상한의 효과를 검증하지 못했습니다.
4. **무관 질의가 6개뿐**이라 가드레일 차단율의 해상도가 낮습니다(한 칸 16.7%p).
5. `region_name`이 전부 "서울"이라(수집 해시태그 기준), 지역 필터의 변별력은 평가되지 않았습니다(WBS 10 지역 확장 후 재평가 필요).
6. **[WBS 8.4에서 추가 확인] 임베딩이 청크의 앞부분만 반영합니다.** ko-sroberta의 입력 한도는 128토큰인데, 청크의 99.0%(3,847/3,884)가
   이를 넘어서 벡터에는 앞부분 약 250자(중앙값 18.7%)만 담깁니다. 이 평가에서 kNN 성능이 좋았던 건 공고 첫 청크에 제목·개요가
   몰려 있기 때문으로 보이며, 통합 공고 뒷부분의 세부 사업 같은 내용은 kNN으로 찾을 수 없습니다(BM25만 가능).
   원인은 청크 크기(정의서 권장 500~800토큰, LLM 컨텍스트 기준)와 임베딩 모델의 입력 한도가 맞지 않는 것입니다.
7. **[WBS 8.4에서 추가 확인] 청크의 토큰 수가 근사치입니다.** `.venv`에 tiktoken이 설치돼 있지 않아 `chunker.py`가
   "글자 수 ÷ 1.7" 근사로 청크를 나눴습니다(3,884개 전부). 청크 크기 해석에만 영향이 있고 이 평가의 수치 자체는 유효합니다.
